## 1. 시스템 개요

### 1.1 두 회사의 특징

**영성ACC (개인회사)**
```
회사명: 영성ACC
사업자등록번호: [개인사업자]
설명: 개인 무역 사업
직원: 소규모 (1-3명)
역할: 주로 영업, 협상
데이터: 작은 규모
```

**와이에스에이씨씨 (법인회사)**
```
회사명: (주)와이에스에이씨씨
법인등록번호: [법인]
설명: 공식 법인 무역회사
직원: 중규모 (10명 이상)
역할: 전체 운영 (영업, 구매, 로지)
데이터: 큰 규모
```

### 1.2 통합 시스템의 이점

```
장점:
  ✓ 하나의 시스템으로 두 회사 관리
  ✓ 공통 API, 데이터베이스 (비용 절감)
  ✓ 회사 간 데이터 공유 가능
  ✓ 통합 보고서 (회사별 분리 가능)
  ✓ 중복 관리 제거

요구사항:
  ✓ 완벽한 데이터 분리 (보안)
  ✓ 회사별 독립적인 권한
  ✓ 회사별 맞춤형 기능
  ✓ 회사 간 통신 기능 (선택)
```

### 1.3 Multi-Tenant vs Single-Tenant

```
Multi-Tenant (통합 데이터베이스):
  ✓ 하나의 DB, 여러 회사
  ✓ 저비용, 관리 용이
  ✓ 회사별 필터링 필요
  ✓ 이 프로젝트에서 선택 ⭐

Single-Tenant (분리 데이터베이스):
  ✓ 회사별 독립적 DB
  ✓ 높은 보안
  ✓ 높은 비용
  ✓ 나중에 필요시 전환 가능
```

## 2. 다중 회사 아키텍처

### 2.1 시스템 구조

```
┌─────────────────────────────────────────────────────┐
│                로그인 화면                           │
│  [Username] [Password] [회사 선택]                  │
├─────────────────────────────────────────────────────┤
│                회사 선택                             │
│  영성ACC / (주)와이에스에이씨씨                      │
├─────────────────────────────────────────────────────┤
│            대시보드 (선택된 회사만)                  │
│  영성ACC의 데이터만 표시                            │
│  또는 (주)와이에스에이씨씨의 데이터만 표시          │
├─────────────────────────────────────────────────────┤
│  모든 API 호출에 회사 ID 포함                       │
│  GET /api/purchase-orders?company_id=영성ACC       │
│  → 영성ACC의 PO만 반환                             │
└─────────────────────────────────────────────────────┘
```

### 2.2 데이터 흐름

```
사용자 로그인:
  1. 사용자명 + 비밀번호로 인증
  2. 해당 사용자가 속한 회사 조회
  3. 회사 선택 화면 (여러 회사 속한 경우)
  4. 선택된 회사의 JWT 토큰 발급
     └─ Token에 company_id 포함
  5. 모든 API에서 company_id로 필터링

API 호출:
  GET /api/purchase-orders
  Header: Authorization: Bearer <token_with_company_id>
  
  백엔드:
    1. 토큰에서 company_id 추출
    2. WHERE company_id = extracted_company_id 필터 추가
    3. 해당 회사의 데이터만 반환
```

## 3. DB 스키마 수정

### 3.1 새 테이블: companies (회사 마스터)

```sql
CREATE TABLE companies (
  company_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_code VARCHAR(50) UNIQUE NOT NULL,        -- 영성ACC, YSACC
  company_name VARCHAR(255) NOT NULL UNIQUE,       -- 영성ACC, (주)와이에스에이씨씨
  company_type VARCHAR(50),                        -- individual, corporation
  business_number VARCHAR(20),                     -- 사업자번호
  ceo_name VARCHAR(100),
  address VARCHAR(500),
  phone VARCHAR(20),
  email VARCHAR(100),
  website VARCHAR(255),
  logo_url VARCHAR(500),
  
  -- 설정
  timezone VARCHAR(50) DEFAULT 'Asia/Seoul',
  currency VARCHAR(3) DEFAULT 'KRW',
  language VARCHAR(10) DEFAULT 'ko',
  
  -- 상태
  status VARCHAR(50) DEFAULT 'active',             -- active, inactive, suspended
  
  -- 추적
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  created_by UUID REFERENCES users(user_id)
);

-- 인덱스
CREATE INDEX idx_company_code ON companies(company_code);
CREATE INDEX idx_company_status ON companies(status);
```

### 4.2 JWT 토큰에 company_id 포함

```typescript
// 토큰 생성 시
const token = jwt.sign({
  user_id: user.user_id,
  username: user.username,
  company_id: selected_company_id,  // ← 핵심! 회사 ID 포함

```

### 4.3 모든 API에서 company_id 검증

```typescript
// 미들웨어: company_id 검증
middleware authenticateCompany = (req, res, next) => {
  // Step 1: 토큰에서 company_id 추출
  const token = req.headers.authorization.split(' ')[1];
  const decoded = jwt.verify(token, SECRET_KEY);
  const company_id = decoded.company_id;
  
  // Step 2: 요청 바디/파라미터의 company_id 확인
  const requested_company_id = req.body.company_id || req.query.company_id;
  
  // Step 3: 일치하는지 확인
  if (requested_company_id && requested_company_id !== company_id) {
    return res.status(403).json({
      status: "error",
      message: "회사 접근 권한 없음"
    });
  }
  
  // Step 4: 다음 미들웨어에 company_id 전달
  req.company_id = company_id;
  next();
};

// API 예시
GET /api/purchase-orders
Header: Authorization: Bearer <token_with_company_id>

백엔드 처리:
  const company_id = req.company_id; // 미들웨어에서 추출
  
  const pos = await db.query(`
    SELECT * FROM purchase_orders
    WHERE company_id = $1
    ORDER BY created_at DESC
  `, [company_id]);
  
  response: { pos }  // 해당 회사의 PO만 반환
```

### 6.3 데이터 조회 시 회사 필터 자동 추가

```typescript
// 미들웨어: 모든 쿼리에 company_id 자동 추가
function addCompanyFilter(req, res, next) {
  const company_id = req.company_id;
  
  // 쿼리 빌더에 회사 필터 자동 추가
  req.queryFilters = {
    company_id: company_id
  };
  
  next();
}

// API에서 사용
app.get('/api/purchase-orders', 
  authenticate, 
  authenticateCompany,
  addCompanyFilter,
  async (req, res) => {
    const { company_id } = req.queryFilters;
    
    // WHERE company_id = $1 자동 추가됨
    const pos = await db.query(`
      SELECT * FROM purchase_orders
      WHERE company_id = $1
    `, [company_id]);
    
    res.json(pos);
  }
);
```

```sql
CREATE OR REPLACE FUNCTION generate_po_number()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.po_number IS NULL THEN
    SELECT company_code INTO company_code 
    FROM companies WHERE company_id = NEW.company_id;
    
    NEW.po_number := 'PO-' || company_code || '-' 
                     || TO_CHAR(NEW.po_date, 'YYYY') || '-'

  RETURN NEW;
END;
```

### 10.2 권한 검증

```typescript
// 회사 권한 확인 미들웨어
function checkPermission(requiredPermission) {
  return async (req, res, next) => {
    const { user_id, company_id } = req;
    
    // Step 1: user_companies에서 역할 조회
    const userRole = await db.query(`
      SELECT role FROM user_companies
      WHERE user_id = $1 AND company_id = $2
    `, [user_id, company_id]);
    
    if (!userRole) {
      return res.status(403).json({
        status: "error",
        message: "이 회사에 접근 권한이 없습니다"
      });
    }
    
    // Step 2: company_permissions에서 권한 확인
    const hasPermission = await db.query(`
      SELECT * FROM company_permissions
      WHERE company_id = $1 
        AND role = $2
        AND ${requiredPermission} = TRUE
    `, [company_id, userRole[0].role]);
    
    if (!hasPermission || !hasPermission.length) {
      return res.status(403).json({
        status: "error",
        message: "이 작업을 수행할 권한이 없습니다"
      });
    }
    
    next();
  };
}

// 사용 예
app.post('/api/purchase-orders',
  authenticate,

  checkPermission('can_create_po'),
  createPO
);
```

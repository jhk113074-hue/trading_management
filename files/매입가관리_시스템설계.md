# 매입가 관리 시스템 설계 (Cost Management System)

## 1. 핵심 개념

### 문제점 (기존)
- 발주서와 견적서가 분리됨
- 매입가를 매번 수동 입력
- 공급사 가격 변동 추적 어려움
- 원가 분석 불가능

### 해결책 (신규)
- **발주서(PO) = 매입가 마스터 소스**
- 매입가는 PO에서만 입력
- PI(견적서)는 자동으로 로드
- 모든 서류가 동일한 원가 기반

### 2.4 발주서 라인 아이템
```sql
CREATE TABLE po_line_items (
  id UUID PRIMARY KEY,

  product_id UUID FK,
  specification VARCHAR(255),
  quantity DECIMAL(10,2),
  unit VARCHAR(50),                     -- KG, PCS

```

### 2.5 매입가 마스터 (Cost Master) ★ 핵심
```sql
CREATE TABLE cost_master (
  id UUID PRIMARY KEY,
  product_id UUID FK,
  supplier_id UUID FK,
  po_line_item_id UUID FK,              -- PO 라인 참조
  po_number VARCHAR(100),               -- PO-2026-001
  unit_price DECIMAL(12,2),             -- 5,000 KRW
  currency VARCHAR(3),                  -- KRW
  unit VARCHAR(50),                     -- KG
  effective_date DATE,                  -- PO 발주일
  is_latest BOOLEAN,                    -- 최신 가격 여부
  version INT,                          -- 1, 2, 3... (공급사 가격 변경 시)
  notes TEXT,
  created_at TIMESTAMP,
  created_by UUID FK
);

-- 인덱스: 최신 매입가 빠르게 조회
CREATE INDEX idx_cost_latest ON cost_master(product_id, is_latest, effective_date DESC);
```

### 2.6 견적서 (Proforma Invoice)
```sql
CREATE TABLE proforma_invoices (
  id UUID PRIMARY KEY,
  pi_number VARCHAR(100) UNIQUE,        -- PI-TMS-2026-01
  pi_date DATE,
  customer_id UUID FK,
  contact_person VARCHAR(100),
  payment_terms VARCHAR(100),
  incoterms VARCHAR(50),                -- CIF, FOB
  destination VARCHAR(255),
  exchange_rate DECIMAL(10,4),          -- 1,468.96
  validity_days INT,                    -- 30
  notes TEXT,
  status VARCHAR(50),                   -- draft, sent, confirmed
  created_by UUID FK,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

### 2.7 견적서 라인 아이템
```sql
CREATE TABLE pi_line_items (
  id UUID PRIMARY KEY,
  pi_id UUID FK,
  product_id UUID FK,
  
  -- 매입가 정보 (자동 로드)
  cost_master_id UUID FK,               -- cost_master 참조
  unit_price_krw DECIMAL(12,2),         -- 5,000 (매입가)
  
  -- 판매가 정보 (자동 계산)
  quantity DECIMAL(10,2),
  unit VARCHAR(50),
  profit_margin DECIMAL(5,2),           -- 0.20 (20%)
  unit_price_usd DECIMAL(12,4),         -- 3.70 (자동 계산)
  total_amount_usd DECIMAL(15,4),       -- quantity × unit_price_usd
  
  created_at TIMESTAMP
);
```

### 2.8 수익 분석 뷰 (자동 계산)
```sql
CREATE VIEW v_profitability AS
SELECT 
  pi.pi_number,
  pil.product_id,
  pil.unit_price_krw,
  pil.quantity,
  pil.unit,
  pi.exchange_rate,
  
  -- 원가 계산
  (pil.unit_price_krw * pil.quantity) AS cost_krw,
  (pil.unit_price_krw * pil.quantity / pi.exchange_rate) AS cost_usd,
  
  -- 판매가 계산
  pil.unit_price_usd,
  pil.total_amount_usd AS revenue_usd,
  
  -- 이익 계산
  pil.profit_margin,
  (pil.total_amount_usd - (pil.unit_price_krw * pil.quantity / pi.exchange_rate)) AS profit_usd,
  ((pil.total_amount_usd - (pil.unit_price_krw * pil.quantity / pi.exchange_rate)) / pil.total_amount_usd * 100) AS profit_margin_percent
  
FROM proforma_invoices pi
JOIN pi_line_items pil ON pi.id = pil.pi_id
JOIN cost_master cm ON pil.cost_master_id = cm.id;
```

  ④ PO 저장 완료
```

### 3.2 견적서 작성 시 매입가 자동 로드

```
사용자가 PI 작성:
  ① PI 폼 입력
     - 고객사: UNION
     - 상품 선택: Cushion Pad
  
  ② 상품 선택 시 자동 처리 (onChange 이벤트)
     ```javascript
     // 최신 매입가 조회
     SELECT * FROM cost_master 
     WHERE product_id = 'cushion_pad' 
     AND is_latest = TRUE
     ```
     결과: { unit_price_krw: 5000, po_number: 'PO-2026-001' }
  
  ③ 폼에 자동 채우기
     - 매입가: 5,000 KRW [읽기전용]
     - 환율: 1,468.96 [수정 가능]
     - 이익률: 20% [수정 가능]
  
  ④ 자동 계산 (실시간)
     - USD 매입가 = 5,000 ÷ 1,468.96 = 3.40 USD
     - 판매가 USD = 3.40 × 1.20 = 4.08 USD
     - 수량: 50 KG → 합계: 204 USD
  
  ⑤ [저장] 클릭 → PI 저장
     - pi_line_items에 저장
     - cost_master_id 참조 설정
```

## 4. 주요 쿼리 (SQL)

### 4.1 최신 매입가 조회
```sql
-- 특정 상품의 최신 매입가
SELECT cm.*, s.name as supplier_name
FROM cost_master cm
JOIN suppliers s ON cm.supplier_id = s.id
WHERE cm.product_id = ?
AND cm.is_latest = TRUE
ORDER BY cm.effective_date DESC
LIMIT 1;
```

### 4.2 상품별 가격 이력
```sql
-- Cushion Pad의 모든 가격 변동 이력
SELECT 
  cm.po_number,
  s.name as supplier_name,
  cm.unit_price,
  cm.effective_date,
  cm.is_latest
FROM cost_master cm
JOIN suppliers s ON cm.supplier_id = s.id
WHERE cm.product_id = ?
ORDER BY cm.effective_date DESC;
```

### 4.3 수익성 분석
```sql
-- 각 견적서의 수익률 조회
SELECT 
  pi.pi_number,
  pi.customer_id,
  SUM(pil.total_amount_usd) as total_revenue_usd,
  SUM(pil.unit_price_krw * pil.quantity / pi.exchange_rate) as total_cost_usd,
  SUM(pil.total_amount_usd) - SUM(pil.unit_price_krw * pil.quantity / pi.exchange_rate) as profit_usd,
  ROUND(
    (SUM(pil.total_amount_usd) - SUM(pil.unit_price_krw * pil.quantity / pi.exchange_rate)) 
    / SUM(pil.total_amount_usd) * 100, 2
  ) as profit_margin_percent
FROM proforma_invoices pi
JOIN pi_line_items pil ON pi.id = pil.pi_id
WHERE pi.status = 'confirmed'
GROUP BY pi.pi_number
ORDER BY profit_margin_percent DESC;
```

### 입력 필드

```
PO 작성 폼
┌─────────────────────────────────────┐
│ PO Number: [자동]  PO-2026-001       │
│ PO Date: [오늘 자동]  2026-01-15    │
│ Supplier: [드롭다운] 폴린트          │
│ Reference: [선택] 조형은 선임님      │
│ Phone: [자동로드] 010-xxxx-xxxx     │
│                                     │
│ ┌─ 상품 1                          │
│ │ Product: [검색] Cushion Pad       │
│ │ Spec: Ø30×25mm                   │
│ │ Qty: 50  Unit: KG                │
│ │ Unit Price (매입가): 5,000 KRW    │
│ │ Total: 250,000 KRW [자동]         │
│ │                                  │
│ │ [이 가격을 기본값으로 저장] ☑     │
│ │                                  │
│ └─ [+ 상품 추가]                   │
│                                     │
│ Delivery Date: 2026-02-28           │
│ Notes: [선택사항]                    │
│                                     │
│ [💾 저장] [📄 PDF] [📧 이메일]      │
└─────────────────────────────────────┘
```

### 저장 시 자동 처리

1. **PO 번호 자동 생성**: PO-2026-001, PO-2026-002...
2. **매입가 DB 저장**: 자동으로 cost_master에 기록
3. **이전 가격 비교**: 동일 상품의 이전 가격과 비교 → 변동 알림
   - "이전: 4,900 KRW → 현재: 5,000 KRW (인상 2.04%)"
4. **PDF 생성**: PO 표준 양식으로 생성 가능

## 6. 견적서 폼 설계 (상세)

### 상품 선택 시 자동 로드

```javascript
// PI 상품 라인 추가 시
<form>
  <select id="product" onchange="loadCostFromDB(this.value)">
    <option>Cushion Pad</option>
    ...
  </select>
  
  <input id="costKRW" readonly 
         placeholder="자동 로드 대기...">
  <input id="costUSD" readonly 
         placeholder="환율 적용 후 계산...">
  
  <input id="exchangeRate" value="1,468.96" 
         onchange="recalculatePrice()">
  <input id="profitMargin" value="20" 
         onchange="recalculatePrice()">
  
  <output id="salePriceUSD" readonly>
    [자동 계산 결과]
  </output>
</form>
```

### 동작 로직

```javascript
async function loadCostFromDB(productId) {
  // DB에서 최신 매입가 조회
  const cost = await api.get(`/api/cost-master/latest/${productId}`);
  
  document.getElementById('costKRW').value = cost.unit_price;
  document.getElementById('costKRW').dataset.costMasterId = cost.id;
  
  recalculatePrice(); // 자동 재계산
}

function recalculatePrice() {
  const costKRW = parseFloat(document.getElementById('costKRW').value);
  const exchangeRate = parseFloat(document.getElementById('exchangeRate').value);
  const profitMargin = parseFloat(document.getElementById('profitMargin').value) / 100;
  
  // USD 환산
  const costUSD = costKRW / exchangeRate;
  document.getElementById('costUSD').value = costUSD.toFixed(2);
  
  // 판매가 (이익률 적용)
  const salePrice = costUSD * (1 + profitMargin);
  document.getElementById('salePriceUSD').value = salePrice.toFixed(2);
}
```

## 9. 기술 스택 제안

### 데이터베이스
- PostgreSQL (트랜잭션, 복잡한 쿼리 지원)
- 인덱싱: product_id, is_latest, effective_date

### 백엔드 API
```
GET  /api/cost-master/latest/:productId      // 최신 매입가 조회
GET  /api/cost-master/history/:productId     // 가격 이력
POST /api/purchase-orders                    // PO 생성 + 매입가 저장
GET  /api/po/:poId                          // PO 조회
POST /api/proforma-invoices                 // PI 생성
PUT  /api/proforma-invoices/:piId           // PI 수정
GET  /api/profitability/summary             // 수익성 요약
```

- React: 실시간 계산 (onChange 이벤트)
